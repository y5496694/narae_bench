## 모델과 학습 범위

나래1은 Qwen3-0.6B, 나래2는 EXAONE-3.5-2.4B-Instruct에 실제로 학습한 기존 SFT v1 어댑터입니다. 두 어댑터는 각각 3 epoch·156 optimizer step을 수행했고, 원본 safetensors와 F32 GGUF의 24개 텐서 일치를 확인했습니다. 이번 재평가 중 추가 가중치 학습은 하지 않았습니다. Ollama의 동명 프롬프트 프로필을 학습 모델로 평가하지 않았습니다.

기존 학습 자료는 단일 응답 208개(업무 분기 144·인용 56·확인 불가 8)이고 여러 단계의 도구 사용 궤적은 0개입니다. 따라서 이번 결과로 분기·인용 학습이 여러 단계 업무 수행 능력으로 이어졌다고 볼 수 없습니다. 다음 SFT에는 벤치 정답과 별개로 만든 도구 호출·관찰·오류 수정·완료 보고 궤적이 필요합니다.

대안 Qwen3-4B-Instruct-2507은 나래 추가 학습 전 원본 지시 모델을 Q4_K_M으로 실행했습니다. 4B를 학습된 나래 모델로 부르지 않습니다. 각 upstream/quantization revision도 `serving/qwen4b.json`에 기록했습니다.

## 수정과 해석

이전 네이티브 실행기는 스트리밍 응답의 불완전한 토큰 ID 배열을 다시 디코딩해 한글 바이트 일부를 잃었습니다. 해당 잠정 점수는 무효로 분리했고 이번 표에 포함하지 않았습니다. 이번 실행은 UTF-8 API `message.content`와 최종 `usage`를 사용합니다. [실제 전송 재현 자료](verification/lossless-stream-probe.json)와 한국어 왕복 회귀 테스트를 남겼습니다.

v2.1은 요청한 검색 필터가 맞고 `has_more:false`이면 단일 페이지의 실제 전체 조회를 인정합니다. 불필요한 `all_pages:true` 요청 플래그가 없다는 이유로 실패시키던 채점 오류를 수정했으며, 필터 일치와 다중 페이지 누락 검사는 유지합니다. 모델별로 서로 다른 채점기를 쓰지 않았습니다.

Qwen 4B 실행은 32개 완료 뒤 상태 파일 교체의 Windows 잠금 오류로 상위 실행기가 종료됐습니다. 완료된 32개는 보존하고 남은 CBE-08~11은 같은 가중치·서버 설정·공개 실행기로 새 상태에서 다시 실행했습니다. 중단 중이던 CBE-08의 불완전한 대화는 제외했습니다. [복구 기록](verification/qwen-recovery.json)에 원인과 재실행 범위를 남겼고, 최종 108개 과제 감사에는 복구된 4개를 포함합니다. 연결 오류 자체를 모델의 업무 오답으로 채점하지 않았습니다.

결과는 공개 모의 과제에서 얻은 한 번의 고정 seed 측정입니다. 평가 환경 작성자는 벤치 코드를 미리 보았고 독립적인 의미 검수도 수행하지 않았습니다. 별도 v1 Codex 자체 점수 81.09는 노출·도움 스크립트·예산 조건이 달라 이 표와 비교할 수 없습니다.

## 파일

각 모델 폴더의 `model-transcript.jsonl`에는 요청 본문·실제 응답·도구 관찰을, `evidence/`에는 모의 상태와 도구 호출 증거를 담았습니다. 공개된 내용은 모두 가상 평가 자료이며 실제 계정·학교 문서·API 키를 포함하지 않습니다. `results.json`과 `summary.json`으로 집계를 재검산할 수 있습니다. 로컬 절대 경로는 원본 출처 기록이며 다른 PC에서는 본인의 경로를 지정해야 합니다.

`recipe/`는 이 PC에서 사용한 비교·검증 소스 사본입니다. 별도 PC에서 다른 모델을 돌릴 때는 저장소의 `mock/evaluate.py --base-url ... --model ... --out ...`를 사용하세요. 추론 서버 설치·모델 다운로드·모델 라이선스 확인은 별도로 필요하며 가중치는 이 저장소에 포함하지 않습니다.
