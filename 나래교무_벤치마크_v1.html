이 묶음 전체를 평가 AI의 작업 폴더에 제공하지 않습니다. 실행기는 과제·입력 첨부만 별도 폴더로 복사하고, gold·참고 답안·다른 케이스 결과는 접근 범위 밖에 둡니다. prepare는 이 격리를 자동으로 강제하지 않습니다. 공개 샘플로 절차를 개선한 뒤 최종 비교에는 새 주제/기관명/조건의 비공개 세트를 고정해 사용합니다.

실제 결재자·수신기관은 approver_1 / reviewer_1 / recipient_1 바인딩으로만 지정합니다. 빈 바인딩이나 가상 기관 이름을 실제 업무에 넣지 않습니다. 전용 과제카드가 필수인 기관은 평가자가 그 명칭·ID도 사전 제공하며 별도 필수값으로 대조합니다. 모든 과제에 실행별 고유 run tag를 붙여 이름 충돌을 피합니다.

6. 실행·기록 순서

  1. 환경과 허용 범위 고정: 로그인/1회 허용 완료, 기관·계정·권한·스킬/도구 버전 확인. 지원표는 실행 전에 동결합니다. mock/live-prep/live-send를 선택하고 기존 세션 gyomu를 확인합니다. CBE 전송 트랙에는 지정 시험 수신자·방·본문·파일의 명시적 전송 지시가 필요합니다.
  2. 정답 fixture 준비: 실제 문서 ID·날짜 기준·기안/접수/결재 이력, 공람 상태, 서식명, 나이스 복무/결재선, CBE 사용자/방/본문/첨부 gold를 별도로 보관합니다. 조회 결과는 시험 직전 스냅샷으로 동결합니다. 실서비스에서 가상 조직·교직원을 임의 생성하지 않습니다.
  3. 첨부 확장자 준비: HWP·HWPX·텍스트 PDF·DOCX·XLSX·PPTX·스캔 PDF/PNG의 실제 바이너리와 각 형식의 gold를 준비합니다. 본 패키지에는 이 7종 바이너리·학교 서버용 모의 UI가 포함되지 않습니다. 공통 가상 원문과 형식별 설계표만 제공합니다. 파일의 이름만 바꿔 확장자를 위장하지 않습니다.
  4. 새 run 생성: 아래 prepare 명령을 실행합니다. 기존 폴더는 덮어쓰지 않습니다. bindings.json을 채우고 각 과제 프롬프트의 중괄호를 허용된 실제 값으로 바꿉니다. 생성된 작성 사례의 날짜는 2026년 가상 값이므로 다른 시점 시험은 평가자가 새 날짜 프로필과 gold를 함께 고정합니다.
  5. 초기 상태 복원·실행: 케이스별 별도 컨텍스트/동일 예산으로 시작하며 다른 케이스의 정답을 넘기지 않습니다. 연결 흐름은 별도 관찰합니다. 필수 질문에 대한 평가자 응답은 대본대로 제공하고, 복구 과제는 모의 환경에서만 장애를 주입합니다.
  6. 독립 대조·집계: results.json의 체크에 true/false/null, 증거 파일 경로, 실패 분류를 기록합니다. PASS는 모든 체크가 참이고 증거가 있을 때만 적습니다. NOT_RUN은 미평가입니다. 오류 주입 과제의 정상 감지 성공은 status=PASS, failure_layer=NONE으로 기록하고 주입 오류는 notes에 적습니다.
  7. 종료 상태 관리: 실행기·keepalive를 종료하고 시험 초안·첨부 업로드·메시지의 생성 ID를 기록합니다. 실제 삭제·회수는 별도 사용자 지시 범위에서 처리합니다. 시험 종료를 원문이나 실제 업무 이력의 임의 삭제로 구현하지 않습니다.

python bench.py grade D:\Codex\workspaces\narae-bench-run-001\results.json --out D:\Codex\workspaces\narae-bench-run-001\summary.json

bench.py는 Python 표준 라이브러리만 사용합니다. 학교 시스템에 연결하거나 AI를 호출하지 않습니다. prepare는 과제·빈 기록표를 만들고, grade는 사람이 검수한 기록을 집계합니다. 증거의 내용이 실제로 맞는지는 자동 판정하지 않으며, 파일 존재와 항목 구조만 검사합니다. lint-body는 일부 텍스트 형식만 검사합니다.
